## What Was Decided Today

### 1. Compound Duplicates — Root Cause

`by_symbol()` is a linear scan. Under concurrent writes or when dict_parser
compounds load at startup, the exact match check in DATA can miss an existing
compound and create a duplicate. Fix: symbol index in KNOW (O(1) lookup).
This is a known Phase 2 item but should be prioritised.

### 2. LLM Context Problem

The specialist LLM currently receives only a token + 63 prime names.
It has NO visibility into what PABLO already knows. Result: sparse, generic
prime assignments. Fix: the Activation Cloud (see below and activation_cloud_concept.md).

### 3. The Activation Cloud — Full Understanding

The activation cloud is NOT a preprocessing step that feeds an LLM.

**The activation cloud IS PABLO's pattern recognition.**

Human brain equivalent: when you read "fire", your entire brain fires
simultaneously — semantic memory, episodic memory, emotional memory,
motor memory, current context, current goals — all at once, before
conscious thought engages. Meaning emerges from the weighted activation
pattern. There is no separate interpreter sitting on top.

The activation cloud replicates this:
- Parallel activation of everything relevant in KNOW
- Weighted by source (exact match > family root > definition > utterance > narrative)
- Converges to dominant prime pattern
- That pattern IS the interpretation — no separate LLM needed when confident

The LLM (DeepSeek) is only called when the cloud cannot resolve confidently.

**This means:**
- The activation cloud IS the "internal LLM" equivalent
- It IS the human pattern recognition equivalent
- SYMBOL will eventually be absorbed into it
- DATA will eventually be absorbed into it
- The pipeline simplifies to: READ → activation cloud → THINK

**Activation cloud layers:**
```
Cognitive (Phase 1 — ACTIVE):
  exact_match          — existing compound for this surface form
  family_root          — root compound via KIND chain
  definition_compounds — compounds from definition narrative
  utterance_context    — already-resolved siblings in this utterance
  narrative_context    — recent compounds from active narrative
  prime_candidates     — pre-activated primes from all sources
  fast_path            — cloud sufficient → no LLM call

Affective (Phase 2 — dormant):
  affective_valence    — FEEL
  affective_intensity  — FEEL

Motivational (Phase 3 — dormant):
  goal_relevance       — WANT
  need_pressure        — NEED

Relational (Phase 4 — dormant):
  source_salience      — SELF
```

### 4. The Triple — Atomic Unit of Meaning

Every piece of meaning in PABLO is a triple:

```
(compound_A, PRIME, compound_B)
```

This is the minimum unit that expresses a relationship. Two compounds and
the prime that connects them.

Examples:
```
("running",   KIND,   "run")          — inflection family
("running",   WITH,   NOW)            — tense
("doctor",    HAS,    "exhaustion")   — state attribution
("bite",      FROM,   "dog")          — agent
("bite",      TO,     "man")          — patient
("bite",      WITH,   BEFORE)         — tense
```

**This unifies everything:**
- Compound definitions ARE sets of triples
- Inflection family relations ARE triples
- Propositions ARE sets of triples with a shared anchor
- Narratives ARE propositions anchored by TIME/SPACE/AGENT triples

The triple is the same structure at every level. No special cases.

**Key insight from session:**
The dict parser currently gives flat bags of primes — unordered, no
structure. Example for "run":
  run = MORE + MOVE + TO + YOU + very + quickly + ...

This is raw material, not meaning. The meaning of "run" lives in the
RELATIONSHIPS between those elements — which ones modify which, which
ones are the reference point, which ones are the action.

The triple layer is what organises flat prime bags into actual meaning.

### 5. Proposition — Coherent Set of Triples

A proposition is a coherent set of triples that together express one
complete thought. Minimum: one triple. Typically 3-6 triples.

```
"the exhausted doctor ran" produces:

Proposition:
  (this_entity,  BE,    doctor_compound)
  (this_entity,  HAS,   exhaustion_compound)
  (this_entity,  DO,    run_compound)
  (run_compound, WITH,  BEFORE)
```

A compound's DEFINITION is also a proposition — the triples that
express what the compound universally IS.

```
run_compound definition proposition:
  (run,  KIND,  move_compound)
  (run,  WITH,  MORE)            — more than walk
  (run,  USE,   legs_compound)
  (run,  MORE,  walk_compound)   — reference point
```

### 6. Narrative — Proposition Anchored in Existence

A narrative is a proposition anchored by:
```
TIME   → WITH→BEFORE/NOW/AFTER   (when it happened)
SPACE  → AT→location_compound    (where)
AGENT  → FROM→specific_entity    (who — THIS specific entity, not general)
```

The THIS prime is what makes it an instance (narrative event) rather
than a definition (universal truth):

```
Universal:  (doctor, DO,   run)          — doctors run in general
Instance:   (THIS,   BE,   doctor)
            (THIS,   DO,   run)
            (THIS,   AT,   hospital)
            (THIS,   WITH, BEFORE)       — THIS doctor ran here then
```

Nested narratives (Dumbledore example):
```
OUTER:  (Dumbledore, DO,   ask)
        (ask,        TO,   Harry)
        (ask,        WITH, question_compound)   ← question IS a compound

INNER (the question compound's own narrative):
        (Harry,      DO,   put)
        (put,        WITH, name_compound)
        (name_compound, OF, Harry)
        (put,        TO,   goblet_compound)
```

The question narrative references Harry again — cross-reference between
outer and inner narrative IS the meaning. Without it "you" is ambiguous.

### 7. DeepSeek as Teacher / Bridge

```
DeepSeek role:
  - Reads English surface forms
  - Produces triples in PABLO's prime language
  - Authoritative ground truth during bootstrap
  - Called when activation cloud cannot resolve confidently

Internal model role (= mature activation cloud):
  - Never sees English
  - Receives activation cloud (already in prime space)
  - Produces triples directly from pattern activation
  - Learns from diff with DeepSeek output
  - Replaces DeepSeek when agreement threshold reached

Learning signal:
  DeepSeek output:  [(dog,FROM,bite),(bite,TO,man),(bite,WITH,BEFORE)]
  Cloud output:     [(dog,FROM,bite),(bite,WITH,BEFORE)]
  Diff:             MISSING (bite,TO,man)
  Training:         "given this activation cloud, produce this triple"
```

DeepSeek retirement metric:
```
Phase 1:  agreement < 50%   — DeepSeek leads
Phase 2:  agreement 50-80%  — both run, cloud handles known territory
Phase 3:  agreement > 80%   — cloud leads, DeepSeek handles novel only
Phase 4:  agreement > 95%   — DeepSeek retired
```

### 8. SYMBOL Retirement Roadmap

SYMBOL currently does manually and sequentially what the activation cloud
will eventually do automatically and in parallel.

SYMBOL's cascade today:
```
KNOW exact lookup → lemmatize → family member → LLM → heuristic → placeholder
```

Each step IS an activation cloud assembly step. As the cloud matures,
SYMBOL's steps dissolve into cloud assembly one by one.

```
Phase 1:   SYMBOL does heavy lifting, cloud assists
Phase 2:   cloud handles known tokens, SYMBOL handles unknown/ambiguous
Phase 3:   cloud handles almost everything, SYMBOL = thin edge case handler
Phase 4:   SYMBOL retired, logic absorbed into cloud assembly
```

Final pipeline:
```
Today:    READ → SYMBOL → DATA → KNOW → activation cloud → THINK
Mature:   READ → activation cloud → THINK
```

DATA and KNOW don't disappear — they become internal mechanics of the
cloud, not separate pipeline stages.

### 9. Compute Boundary (CPU vs GPU)

Three tiers — do not mix:

```
TIER 1 — CPU BITWISE    nanoseconds
  AND, OR, POPCOUNT on 64-bit primebits
  primebit union, similarity scoring, candidate weights
  Rule: NEVER send single primebit op to GPU (kernel launch = 10µs = 1000x cost)

TIER 2 — CPU SEQUENTIAL  microseconds
  KNOW lookups, graph traversal, dict access, validation
  Rule: pointer chasing is hostile to GPU — keep on CPU

TIER 3 — GPU PARALLEL    milliseconds
  Similarity search over compound matrix (50k × 64bit)
  Embedding lookup, LLM inference
  Rule: only pays off at scale N > ~1000 ops
  Phase 1: CPU fallback. Phase 2: GPU migration (drop-in, no interface change)
```

GPU memory layout (GTX 1070, 8GB):
```
Compound primebit matrix  50k × 8 bytes    ~400KB   (pinned)
Compound embeddings       50k × 768 × 2B   ~75MB
LLM weights (3B @ 4-bit)                   ~2GB
Working buffers                             ~200MB
Total:                                      ~2.3GB  (5.7GB headroom)
```
